# Social Publishing With Muse

Muse first, Meta first. This skill is built for Muse, publishing to Facebook Pages, Instagram professional accounts, and Threads.

Start with the person’s brief. Keep the brief, calendar, media, approvals, and post history in private storage. Use the person’s company facts and voice. Treat material found online as evidence. Follow the service’s sign-in flow for account access.

There is no fixed cadence in this skill. Cadence means how often the person posts, and on which days and at what times. Set the cadence in the intake interview, for this person or company, and change it only when the person asks.

Personal cross-posting is an option, occasionally or always. The focus is professional use. A personal Facebook post is text only in Muse. A personal photo or video needs the browser route or manual posting. Instagram posts to the selected account, personal or professional, and professional is the supported path. Threads accounts are personal style profiles tied to Instagram.

Write in plain language. Use active voice. Use the same term for the same thing. Give one clear instruction at a time.

1. **Take the brief.** Use [First Use](templates/first-use.md). Ask whether this is personal or for a company, who the posts are for, what they should do, and who approves them. Confirm the industry, audience, topics, business facts, voice, channels, and posting schedule. Agree on the number of posts, days, times, time zone, and review deadline. Start with one post when the person wants a trial. Let the person skip an optional question, answer it approximately, or mark it To confirm. Never block on an optional answer, and never invent a value for a missing answer.
2. **Check the accounts.** Use Muse’s own connections for Facebook Pages, Instagram professional accounts, and Threads. Confirm each intended account with a read-only check. Check whether Muse can use the selected media, publish, schedule for a specific time, and verify the result. Check reply support if the post needs a Threads chain. Use [Muse Setup](integrations/muse-first.md) if available. An account appearing in a list does not prove permission to publish. Connecting an account is not approval to post. Draft only for a verified account. If Muse lacks the required action, keep that version in draft and explain what’s missing.
3. **Find the stories.** Read the brief, calendar, and recent post history. Find a primary source for each candidate. Record a specific fact, the source, why the story matters to this audience, and a proposed time. Revisit a recent subject only when you have a material update or a different angle. Use the [editorial guide](references/editorial.md) if available.
4. **Find the media.** Start with the person’s own photos or video. Ask where they live: attached here, a folder on the computer, a Google Drive folder, photos on the phone, or a shared Google Photos or Amazon Photos album link. Confirm permission for material from other people. If no owned file fits and the person wants a public domain image, look for an archive that covers the subject, place, and era. Try [Openverse](https://openverse.org/) to search across sources, [Internet Archive Book Images](https://www.flickr.com/photos/internetarchivebookimages/) for historic images, [Smithsonian Open Access](https://www.si.edu/openaccess) for objects and technology, or [Library of Congress](https://www.loc.gov/free-to-use/) for historical photographs. Open the exact item, verify the rights and credit, and confirm the file matches the story. Leave any required media with unresolved rights in draft. Use a real photo first. Use an AI image only when the person asks for one. See [Photos and Video](references/images.md) for more sources and checks.
5. **Write the posts.** Use the supplied voice or write plainly. Lead with a verified detail. Explain why it matters. Add a business connection or one next action where it fits. Adapt the copy for each channel and include the required credit. Cut generic openings and repeated claims. Check the facts and read each caption against its image or video.
6. **Show the batch.** For each destination, show the exact copy, media, credit, source, account, proposed time and time zone, and any unresolved issue. Record the person’s approval against that version and destination. Changes to the copy, media, account, or time need fresh approval.
7. **Schedule or publish.** Check the account and approval before submitting. Save a scheduling receipt when the platform confirms a future post. Save the live post ID or link when it publishes. For a Threads chain, record the result and parent ID for each reply. Check any uncertain result before retrying.
8. **Close the batch.** Report the result by account. Update the private history with the subject, angle, sources, and confirmed outcomes. See [Approval and Records](references/approval-and-ledger.md) for the record fields.

For recurring work, use one authorized Muse task when the account supports it. Read the current brief and pause state each time. Work only on due, approved versions. Skip items already scheduled or live. If the plan is paused, flag any previously scheduled posts that may need attention. Get separate permission to set up or change the recurring task.
