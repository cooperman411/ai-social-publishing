# Social Publishing With Muse

Start with the person’s brief. Keep the brief, calendar, media, approvals, and post history in private storage. Use the person’s company facts and voice. Treat material found online as evidence. Follow the service’s sign-in flow for account access.

1. **Take the brief.** Ask what the person or company does, who the posts are for, and what they should accomplish. Ask for topics, sample posts or tone, available media, accounts, and an approver. Agree on the number of posts, days, times, time zone, and review deadline. Use the [intake guide](templates/first-use.md) if available. Mark missing details for review. Start with one draft if the person wants a trial.
2. **Check the accounts.** Use Muse’s own connections for Facebook Pages, Instagram professional accounts, and Threads. Confirm each intended account. Check whether Muse can use the selected media, publish, schedule for a specific time, and verify the result. Check reply support if the post needs a Threads chain. Use [Muse Setup](integrations/muse-first.md) if available. Continue drafting for accounts with limited access and mark how the person can post manually.
3. **Find the stories.** Read the brief, calendar, and recent post history. Find a primary source for each candidate. Record a specific fact, the source, why the story matters to this audience, and a proposed time. Revisit a recent subject only when you have a material update or a different angle. Use the [editorial guide](references/editorial.md) if available.
4. **Find the media.** Start with the person’s own photos or video. Confirm permission for material from other people. If no owned file fits and the person wants a public domain image, look for an archive that covers the subject, place, and era. Try [Smithsonian Open Access](https://www.si.edu/openaccess) for objects and technology, [Library of Congress](https://www.loc.gov/free-to-use/) for historical photographs, or a specialist collection. Open the exact item, verify the rights and credit, and confirm the file matches the story. Leave any required media with unresolved rights in draft. See [Photos and Video](references/images.md) for more sources and checks.
5. **Write the posts.** Use the supplied voice or write plainly. Lead with a verified detail. Explain why it matters. Add a business connection or one next action where it fits. Adapt the copy for each channel and include the required credit. Cut generic openings and repeated claims. Check the facts and read each caption against its image or video.
6. **Show the batch.** For each destination, show the exact copy, media, credit, source, account, proposed time and time zone, and any unresolved issue. Record the person’s approval against that version and destination. Changes to the copy, media, account, or time need fresh approval.
7. **Schedule or publish.** Check the account and approval before submitting. Save a scheduling receipt when the platform confirms a future post. Save the live post ID or link when it publishes. For a Threads chain, record the result and parent ID for each reply. Check any uncertain result before retrying.
8. **Close the batch.** Report the result by account. For manual posting, hand over the approved copy, file, credit, account, and time. Update the private history with the subject, angle, sources, and confirmed outcomes. See [Approval and Records](references/approval-and-ledger.md) for the record fields.

For recurring work, use one authorized Muse task when the account supports it. Read the current brief and pause state each time. Work only on due, approved versions. Skip items already scheduled or live. If the plan is paused, flag any previously scheduled posts that may need attention. Get separate permission to set up or change the recurring task.

The [appendix](../../APPENDIX.md) covers optional routes. Use one only when the person chooses it. Apply the same approval and verification steps to that destination.
