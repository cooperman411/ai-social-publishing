# Publishing checklist

This package is intentionally a **new, independent project**. Never copy an
old private repository, reuse its Git history, or paste real workflow logs.

1. Review every file for personal names, account identifiers, customer data,
   private brand/product references, access tokens, and absolute file paths.
   The included sample domains are reserved documentation examples.
2. Create a **new empty** GitHub repository. Do not fork or import a private
   repository. Keep the repository private until final review if preferred.
3. Before the first commit, verify the Git author identity and address. Set a
   public pseudonym and your actual GitHub-provided **noreply** email in local
   Git configuration. Do not use a personal email or name in commit metadata.
4. Add the supplied files to the new repository, run the offline example tests,
   and examine the staged diff. Commit only after this privacy review.
5. Confirm the public README, license, sample data, release assets, and first
   commit metadata disclose no private identity or client information.
6. Publishing a skill is not proof that any live API, paid data, scheduling,
   or outreach action has been tested. Keep the status statement accurate.

No GitHub publishing credential is included. This bundle has no history and
contains no configured Git remote.
